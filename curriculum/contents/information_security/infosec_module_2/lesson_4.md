# Compliance & Security Frameworks

## Why Frameworks Exist

Security frameworks are structured sets of guidelines, best practices, and controls that organizations use to manage their security posture. Instead of starting from scratch, you adopt a proven structure.

---

## Key Frameworks

### NIST Cybersecurity Framework (CSF)
Developed by the US National Institute of Standards and Technology. Organized around five core functions:

| Function | What It Means |
|----------|--------------|
| **Identify** | Know your assets, risks, and environment |
| **Protect** | Implement safeguards |
| **Detect** | Monitor for threats |
| **Respond** | Act when an incident occurs |
| **Recover** | Restore operations and learn |

Free, flexible, and widely adopted globally.

### ISO/IEC 27001
International standard for an **Information Security Management System (ISMS)**. Provides a systematic approach to managing sensitive information. Organizations can be **certified** against it.

Key difference from NIST: ISO 27001 is auditable and certifiable. NIST CSF is a guidance framework.

### Others Worth Knowing
| Framework | Focus |
|-----------|-------|
| **CIS Controls** | Prioritized, actionable security controls |
| **SOC 2** | Service organization controls (cloud/SaaS) |
| **PCI DSS** | Payment card data security |
| **HIPAA** | Healthcare data in the US |

---

## Compliance vs Security

**Compliance** = meeting the minimum requirements set by a standard or regulation.
**Security** = actually protecting your systems.

> Being compliant does not mean you are secure. But being secure usually satisfies compliance.

Compliance gives you a checklist. Security requires judgement.

Frameworks let you map your existing controls to their requirements. This gap analysis shows you what's covered and what's missing — the starting point for any security improvement program.
